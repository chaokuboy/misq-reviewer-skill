# 冒烟测试（Smoke Test）

克隆安装本 skill 后，用下面的用例验证它是否按设计工作。
两个用例各约 5 分钟，跑完即可确认"装对了、行为符合预期"。

## 测试前准备

- Claude Code / Cursor：按根 README 安装后，在**任意项目**里发起对话（skill 需在其 skills 目录内被加载）。
- Codex：`cd` 进本仓库目录后启动 `codex`（自动读 `AGENTS.md`）。
- 其他工具：用系统提示词加载 `SKILL.md` 后同样可测。

## 用例一：模式 ② 投稿可行性诊断（参考 `case_a_misq_diagnosis.md`）

把 `case_a_misq_diagnosis.md` 里的"输入（用户粘贴版）"整段贴给助手，然后对照"预期输出特征"检查。

**通过标准（全部满足才算生效）**：

| # | 检查点 |
|---|---|
| 1 | 会话开头出现功能选择（① 追问 / ② 诊断），或由触发词直接进入 ② 且不啰嗦 |
| 2 | 输出为六段报告：① 可行性 ② 创新点 ③ 缺口清单 ④ 补充建议 ⑤ 不足审计 ⑥ 开放问题 |
| 3 | ⑤ 的每条不足都**标注档案来源**（SB / M22C / M22Q / TB / CO / 49x / 画像维度 8 行号），并附论文证据与严重度 |
| 4 | 全文**没有**"若我是审稿人，我会打……"式的无来源自创观点 |
| 5 | 用 2025 源（49:1–49:4）评 2021 稿时标注了"当代镜头" |
| 6 | 对本文的关键判定与参考答案一致：IS 台前（面包箱通过）、因果识别与声明匹配、方法创新（ML 工具变量）对识别必要、可冲 MISQ |
| 7 | 参考答案里"命中项"与"放行项"的分类方向基本一致（措辞可不同，来源纪律不能丢） |

> 助手输出**不必**与参考答案逐字相同——参考答案记录的是 2026-09 的档案状态；
> 若日后画像/新 Editorial 更新，结论口径可以演进，但上述 7 条结构纪律应保持。

## 用例二：模式 ① 苏格拉底追问（参考 `case_b_socratic.md`）

把 `case_b_socratic.md` 里的"输入（用户粘贴版）"贴给助手。

**通过标准**：

1. 先出现功能选择；用户选 ①（或输入命中触发词）后进入追问，而不是直接开讲。
2. 追问是**一次一个问题**，不一次抛出十个问题；问题锚定画像维度（1 边界 → 6 热点 → 2/4 贡献/拒稿 → 5/2 创新）而非自由联想。
3. 只指出与档案标准的差距，不否定式评价、不代写方案。

## 常见失败与排查

| 症状 | 原因 |
|---|---|
| 助手不知道自己是 MISQ 小助手 / 直接当普通对话 | skill 没被加载：确认目录结构（`SKILL.md` 与 `profiles/` 同在，不能只复制 SKILL.md） |
| 输出没有 ⑤/⑥，或 ⑤ 无来源 | 用了旧版 `SKILL.md` / `misq.md`：拉最新后再试 |
| 出现"审稿人会觉得……"且无档案依据 | 宿主模型未遵守铁律：重述"判断须命中 profiles/misq.md 维度 8 并标注来源"后再问一次 |
