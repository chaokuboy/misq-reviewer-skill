# 证据规则与知识卡

## 来源等级不是判断强度

- `policy`：已核实的正式投稿政策，记录具体适用期刊、类型与日期。
- `editorial`：编辑建议，不自动变为硬门槛。
- `methodology`：方法作者的观点，按研究范式、主张和边界应用。
- `case`：已发表案例，说明可行路径，不能估计录用概率或证明某方法必需。
- `synthesis`：维护者综合推断，显式标注，不能冒充原文表述。

仓库旧画像和九份蒸馏尚未在本轮逐篇对照原文，状态统一为 `unverified`。
保留原始蒸馏便于溯源，但其中“必需、禁止、底线”等语言必须通过适用性与原文核验。
矛盾时不要静默选更严格的说法：回到来源，分清范式和主张；不能核实时降低判断强度。

## 时效

评估时点默认当前投稿时点；历史评估用用户指定时间。来源日期晚于评估日期才标“当代镜头”，
不能作为历史硬伤。仅有年份时：不同年可比较；同一年但先后未知标“时序待确认”。
2022 的材料不能自动作为 2021 标准；2025 的材料也不应永久标为当代镜头。
原文讨论过去的传统，不能据此假定当时已有相同政策。

## 卡片最小格式

使用 JSON（本地完整卡保存在 `.local/cards/`）。每卡字段：
`id, kind, claim, applies_to, exceptions, source, verified, tags`。
`source` 为对象：`title, doi, zotero_key, attachment_key, date, locator, evidence`。
`locator` 为原文 PDF 页码/章节；`evidence` 是支持主张的短片段。
未核实字段用 null，不猜 DOI、作者、页码。核验状态只有逐条比对主张、片段、适用性后才改 true。
公开卡不保存受限全文；短摘录也应最小化。无完整原文可先保留未核验候选。

案例卡另加 `research_question, author_claim, analyst_interpretation, design, findings, limitations`；
任何未知字段为 null，未读全文不把摘要未提的内容记成缺失。来源一致的多卡互链，避免重复计权。

## 检索与报告

先检索相近问题和方法，再检索竞争解释/例外，按需读取命中片段上下文。
检索结果只是候选证据，排名不代表权威；查到关键词也不代表支持主张。
文本索引若仅来自 Zotero 的无分页全文，定位标明“Zotero 索引文本”，需要 PDF 页码时另行核对。
表外已核验原文可支撑补充证据项，但不自动升级为通用期刊规则。
稳定审计 ID 的出处以画像对应行为准；不同范式的补充观点另列来源与核验状态，
不能用问题大致相似代替出处匹配。未核验观点只能提示检查，一般方法推理须注明其性质。
知识库无覆盖时提一般逻辑澄清问题，注明未找到期刊特定依据，不编案例。

## 来源引用与失效检查

卡片 source 可追加 `document_ids`（索引内 ID 数组）、`document_hashes`（ID → 原文文本 SHA256）。
`cards-audit --version ...` 报告来源缺失、字面摘录未命中和文本变化；不自动改变 verified。
没有 document_ids 的旧卡保留，但报告无法自动追溯。`conflicts_with` 可列已知冲突卡 ID，
工具只展示声明，不自动发现语义矛盾。核验过的卡遇到来源变更时，使用前必须重新检查。

`search --year-from/--year-to` 过滤来源日期；未知日期被排除，不能误当窗口内。
`packet` 将原文候选与标准卡分开：文献年份筛选不排除历史编辑建议，仍需人工按评估时点判断。
`read --context 1` 可查物理页前后上下文，片段有重叠，不能重复计为多份证据。

模型辅助语义复核使用 quality-lab.md 的队列和提交格式；`machine_review` 不等于人工 verified。
案例的 field_evidence 指向支持对应字段的原文，避免用一处摘要支撑所有设计/局限判断。
原文包含更正/撤稿通知时先检查其影响；元数据检查无记录不能当有效性证明。
